Tag reference

Every task row is [ ] <plan>-<id>. <title> #tag @module +flag %user due:YYYY-MM-DD _done:YYYY-MM-DD — any number of these, in any order, after the title.

PrefixMeaningExample
#tagClassification — any number of these#backend #api
@moduleSingle grouping tag — drives card color via the Module Colors legend above@backend
+flagStatus/priority — any number of these, open-ended+active +urgent
%userAssignee%user1
due:Deadlinedue:2026-09-20
_done:Completion date — a non-empty value marks the row [x]_done:2026-09-15

% was chosen for assignee (over !/$/&/=) specifically to avoid colliding with markdown image syntax (![) and with KaTeX math delimiters ($...$), both already in use elsewhere in this codebase.

Generate a new plan

Pick the genre, not just the verbosity. deepagent_md writes prose to read — an essay free to revisit a theme, where a section doesn't have to equal the sum of its subsections. deepagent_tree/deepagent_tree_md write a structure to build from — every branch owns a disjoint slice, siblings stay the same size/kind of thing, nothing restates an ancestor or reaches below its own level; the two differ only in how much text lands under each heading (one disciplined sentence vs. a full paragraph), not in that discipline. Pick prose for something meant to be read end-to-end; pick a tree when the output will be cut into tickets/specs afterward. See concepts/DEEPAGENT_TREE.md for the full contract and measured failure modes.

Roll up into tasks.md

    
Runs deepagent_task over the plan currently selected in the top bar — compiles container titles and any generated spec_*.md units into the flat tasks.md the Tasks board reads. No LLM call: existing task tags (#backend, +active, %user, etc.) are preserved on re-run, only titles refresh and brand-new leaves get +backlog.
